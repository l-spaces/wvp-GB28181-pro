# PRD：用户关联设备（通道）分配与查询过滤

## 背景

- 系统现有"角色"功能是半成品：`authority` 未使用，权限仅硬编码 `roleId == 1`（管理员判定）。
- 大屏前端（visual/）已完成账号密码登录（任务 bigscreen-auth）。登录后所有用户看到的设备/通道完全相同，无法按用户区分可见摄像头。
- 需求：管理员在 web 管理页为每个用户分配可见通道；非管理员用户登录后只看到/能操作被关联的通道；管理员（roleId==1）自动关联全部，无需配置。

## 需求

### 功能需求

1. **数据模型**：新增用户-通道关联表 `wvp_user_channel`（user_id + channel_id，channel_id 为 `wvp_device_channel.id` 数据库主键）。
2. **管理接口**（仅 roleId==1 可用，复用现有硬编码鉴权模式）：
   - 查询某用户的已关联通道列表；
   - 全量覆盖式保存（delete 该用户旧关联 + batch insert 新集合）。
3. **web 管理页配置入口**：用户管理页（`web/src/views/user/index.vue`）操作列新增"分配设备"按钮 + 弹窗，弹窗内按"设备 → 通道"树形勾选，保存整体提交。
4. **查询过滤（显示级）**：
   - `GET /api/device/query/devices`（设备分页列表）：非管理员只返回其关联通道所属的设备；
   - `GET /api/device/query/devices/{deviceId}/channels`（设备通道分页）：非管理员只返回其关联的通道；
   - 管理员（roleId==1）不过滤。
5. 大屏前端（visual/）不需要改动：它渲染的就是上述两个接口的返回数据。
6. **web 管理端同样按用户过滤（2026-09-09 测试反馈补充，范围扩展）**：
   - 控制台"设备总数/通道总数"（`GET /api/server/resource/info`）：非管理员只统计其关联设备/通道数；
   - 通道列表（`/commonChannel` 页，含行政区划/组织机构页签的 `GET /api/common/channel/list`、`/civilcode/list`、`/civilCode/unusual/list`）：非管理员只返回关联通道；
   - 组织结构树（`GET /api/region/tree/list`、`GET /api/group/tree/list`）：非管理员只显示包含其关联通道的分支（含必要的祖先节点），无关联分支不显示；
   - 管理员（roleId==1）全部不受影响。
7. **报警管理、录制计划过滤（2026-09-09 二次补充）**：
   - 报警列表 `GET /api/alarm/list`：非管理员只返回其关联通道产生的报警（`wvp_alarm.channel_id` 即通道库主键，与关联表同体系）；
   - 录制计划列表 `GET /api/record/plan/query`：非管理员只返回关联到其可见通道的计划（计划本身含通道，按计划下通道与用户可见通道有交集判断，实现取侵入最小方式）；
   - 录制计划关联通道 `GET /api/record/plan/channel/list`：非管理员只返回其关联通道；
   - 管理员不受影响。
8. **设备删除时级联清理关联（2026-09-10 补充，用户确认的语义）**：
   - 删除设备（`DELETE /api/device/query/devices/{deviceId}/delete`）时，同步删除 `wvp_user_channel` 中该设备下所有通道的关联行；
   - 目录同步中被移除的通道（`resetChannels` 删除分支），同样清理其关联行；
   - 设备仅离线/上线（注销、心跳、WVP 重启）不影响关联；
   - 设备删除后重新注册，通道主键变化，需要管理员重新分配（不做自动恢复/迁移）。

### 明确不做（范围外）

- 不做接口级管控（播放/云台/对讲等操作接口不校验关联，用户拿不到未关联 channelId 即无法操作——显示级过滤）；
- 不做按角色分配（仅用户级）；
- 不做设备侧（设备管理页）反向分配入口；
- 不改动 web 端除用户管理页外的其他页面（页面结构与交互不动，仅后端数据按用户过滤）；
- 不做关联数据与通道删除的自动同步清理（通道被删后关联表允许存在失效行，过滤 JOIN 后自然不显示；失效行可在后续任务清理）。

## 约束

- 遵循现有代码模式：Mapper 注解 SQL / SelectProvider、Controller 层硬编码 `roleId == 1` 鉴权（`SecurityUtils.getUserInfo().getRole().getId()`）、PageHelper 分页。
- web 端使用现有 element-ui 组件，不新增依赖。
- 不修改既有接口的出入参结构（过滤只影响返回的数据范围）。
- 多数据库（MySQL/PostgreSQL 等）的初始化脚本同步新增表（至少更新 `script/sql/初始化-mysql-2.7.4.sql`，其余库脚本按现有结构照抄）。

## 验收标准

1. 管理员登录 web → 用户管理 → 对非管理员用户点击"分配设备" → 弹窗显示全部设备/通道树（含当前勾选态）→ 修改勾选并保存成功。
2. 非管理员用户（关联了 2 个通道）登录大屏：设备列表只显示这 2 个通道所属设备；点开设备后通道列表只有这 2 个；播放/云台等点选功能正常。
3. 管理员登录大屏：设备与通道列表显示全部，与改动前一致。
4. 未做任何关联的用户（非管理员）：设备列表为空（合理默认，PRD 确认此行为）。
5. 原有接口对管理员的行为回归不变（web 管理页设备/通道页不受影响，因其登录用户为管理员）。
6. `mvn compile` 通过；web 端 `npm run build`（或 lint）通过。
